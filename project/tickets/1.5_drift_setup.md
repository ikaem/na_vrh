# 1.5 Drift setup

**Epic:** 1, Project foundations (see [epics.md](../epics.md))
**Spec refs:** sections 10 and 14 of [SPEC.md](../SPEC.md) (Data model, Tech stack: Drift)
**Depends on:** 1.2 (done). Do after 1.3, since both edit `analysis_options.yaml`.
**Status:** Todo

## Why
The local database is the core of the app. Set up the tooling and code generation before any tables (1.6 to 1.9), so each table ticket only adds a table and its test.

## Scope
- Add `drift` and `drift_flutter` to the dependencies, and `drift_dev` and `build_runner` to the dev dependencies.
- Add `lib/src/data/database/app_database.dart`:
  - an `AppDatabase` class with `@DriftDatabase(tables: [])`,
  - a constructor that takes a `QueryExecutor`, so tests inject an in-memory database and ticket 1.11 injects the real on-device one,
  - `schemaVersion` returning 1.
- Generate the code with `fvm dart run build_runner build`.
- Do not commit generated files: ignore `*.g.dart` in `app/.gitignore`, and exclude them from analysis in `analysis_options.yaml`.
- Add a test helper in `test/helpers/` that creates an in-memory `AppDatabase`, for reuse by the table tickets.
- Document codegen in `app/README.md`: the command, and that a fresh clone must run it before `analyze`, `test` or `run`.

## Out of scope
- The tables (1.6 to 1.9).
- The migration strategy and migration tests (1.10).
- Opening the on-device database and its Riverpod provider (1.11).
- Running codegen in CI (1.12 must add that step).

## Acceptance criteria
- [ ] `fvm dart run build_runner build` succeeds and creates `app_database.g.dart`.
- [ ] `git status` is clean after generation (generated files are ignored).
- [ ] A test opens the in-memory database from the helper, runs a trivial query, and checks that `schemaVersion` is 1. It was written first and failed before the class existed.
- [ ] `fvm flutter analyze` is clean after generation.
- [ ] The README documents the codegen step.

## Technical notes
- **Native SQLite in tests:** Drift's in-memory database uses the host's SQLite library. The dev machine has `libsqlite3.so.0`, so it should work, but confirm when the first test runs. CI (1.12) must make sure the library exists there too.
- **Dates:** Drift's DateTime storage is a build option that affects the column format, and the spec requires all timestamps in UTC. Decide it before the first table (1.6), with a round-trip test showing that a stored time comes back as UTC.
- **TDD:** the test comes first and fails because `AppDatabase` does not exist yet.

## Decisions
1. **Generated files are not committed.** Committing them would break the one-production-file-per-commit rule and add noisy diffs. The cost is that every fresh clone and CI run needs a codegen step.
2. **`schemaVersion = 1` here,** with the migration strategy deferred to 1.10.
3. **Shared in-memory test helper in `test/helpers/`,** used by all the table tickets.
