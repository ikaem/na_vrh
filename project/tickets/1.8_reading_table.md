# 1.8 Reading table

**Epic:** 1, Project foundations (see [epics.md](../epics.md))
**Spec refs:** sections 6.2, 6.3 and 10 of [SPEC.md](../SPEC.md) (Reading collection, Position estimation, Data model)
**Depends on:** 1.7
**Status:** Todo

## Why
Detection stores every raw GPS sample, not just the final position, so the averaging and triangulation methods can be compared and re-run later, including on old climbs. This table holds those samples.

## Scope
- Add `lib/src/data/database/tables/readings.dart`: a Drift table `Readings`, with the row class named `ReadingRow` (`@DataClassName('ReadingRow')`).

  | Column | Type | Notes |
  |---|---|---|
  | `id` | text, primary key | UUID |
  | `routeId` | text | foreign key to `routes.id`, `ON DELETE CASCADE` |
  | `attemptId` | text | groups the readings from one Detect tap (a UUID) |
  | `lat`, `lon` | real | |
  | `accuracyM` | real | the accuracy radius reported by the GPS fix |
  | `gpsTimestamp` | date and time (UTC) | the time from the GPS fix, not the device clock |

- Add an index on `routeId`.
- Register the table in `AppDatabase` and regenerate (the generated file is committed).

## Out of scope
- Collecting readings and the estimation methods (epic 6).
- Retention of old attempts. SPEC.md leaves it open (section 15).
- An attempts table. Attempts are only a grouping column, as the spec says.

## Acceptance criteria
- [ ] `Readings` exists with the columns above, registered in `AppDatabase`.
- [ ] A test round-trips several readings that share an attempt and one that belongs to another attempt. Values come back equal, and `gpsTimestamp` comes back as UTC with millisecond precision. Written first.
- [ ] Deleting a route deletes its readings, and deleting the expedition deletes them through the route. Inserting a reading for a missing route is rejected. Written first.
- [ ] `build_runner` leaves `git status` clean, and analyze, tests and the format check pass.

## Suggested units
1. The table file.
2. Registration in `AppDatabase`, the index, the regenerated file, and the tests. The tests use the fixture helpers from 1.7.

## Technical notes
- Because only readings are stored for an attempt, a failed attempt (outside the tolerance) can still be re-evaluated later by recomputing the position from its readings. Nothing about the attempt's result is stored besides on the route, when it succeeds.
- Several attempts can exist for one route, so `attemptId` is not unique per route.
- The date handling is the one from 1.6 (UTC text, full precision).

## Decisions
1. **`ReadingRow` for the row class,** following the `Row` suffix convention from 1.6.
2. **No attempts table.** A reading carries an `attemptId`, as in SPEC.md section 10.
3. **Index on `routeId` only,** which is how readings are looked up.
