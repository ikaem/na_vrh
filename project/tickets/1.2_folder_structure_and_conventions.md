# 1.2 Folder structure and conventions

**Epic:** 1, Project foundations (see [epics.md](../epics.md))
**Spec refs:** section 14 of [SPEC.md](../SPEC.md) (testing: pure logic unit-tested without a device)
**Depends on:** 1.1
**Status:** Done, merged in PR #2

## Why
Decide where code lives before there is much of it, so later tickets don't each invent their own layout. The structure should also make the spec's testing rule easy: pure logic (haversine, averaging, route state transitions, duration, search) sits apart from UI and is testable without a device.

## Target layout

```
app/
├── lib/
│   ├── main.dart                 # entry point only
│   └── src/
│       ├── app.dart              # NaVrhApp: root widget, theme
│       ├── home_screen.dart      # placeholder screen, replaced once designs are decided
│       ├── app_router.dart       # later (ticket 1.13)
│       ├── core/                 # shared helpers with no feature knowledge
│       ├── data/
│       │   └── database/         # Drift database, tables, migrations
│       └── features/
│           └── <feature>/
│               ├── data/         # repositories, database access
│               ├── domain/       # plain Dart models and pure logic (unit-tested)
│               └── presentation/ # screens, widgets, Riverpod providers
└── test/
    ├── helpers/                  # shared test helpers, not mirrored from lib
    └── src/                      # mirrors lib/src/
```

This ticket creates only the files marked as existing today: `main.dart`, `src/app.dart`, `src/home_screen.dart`, and their tests. `core/`, `data/database/` and `features/<feature>/` are created by the tickets that first need them, so no empty folders are committed.

## Scope
- Move the code out of `lib/main.dart` into the layout above:
  - `lib/main.dart`: entry point only, importing `package:na_vrh/src/app.dart`.
  - `lib/src/app.dart`: `NaVrhApp`.
  - `lib/src/home_screen.dart`: `HomeScreen`.
- Replace `test/widget_test.dart` with tests mirroring the source paths:
  - `test/src/app_test.dart`
  - `test/src/home_screen_test.dart`
- Write the conventions below in `app/README.md`, in a short "Project structure and conventions" section.

## Conventions to document
- **The app layer:** `main.dart` and the files at the top of `lib/src/` (`app.dart`, `home_screen.dart`, later `app_router.dart`). It composes features. It may import features. Features and `core/` never import it.
- **Home is not a feature.** The current home screen is a placeholder. Its real content will come from other features, so it lives in the app layer. When the designs are decided, it either becomes one feature's screen or stays an app-level shell.
- **Layers inside a feature:**
  - `data/`: repositories and database access.
  - `domain/`: plain Dart models and pure logic (no Flutter, no Drift imports), so it can be unit-tested directly.
  - `presentation/`: screens, widgets, and Riverpod providers.
- **Boundaries:** a feature may use `core/` and `data/database/`. It does not import another feature's `presentation/`. Shared logic between features moves down into `core/`.
- **Imports:** package imports (`package:na_vrh/src/...`), not relative paths, across folders.
- **Why `src/`:** it keeps `lib/` to a single entry file, and matches the Dart package layout. Nothing outside the app imports it, so it is a layout choice, not a privacy boundary.
- **Tests:** a test mirrors its source path. `lib/src/x.dart` is tested by `test/src/x_test.dart`. Shared helpers (provider overrides, in-memory database, router pumping) live in `test/helpers/`. `main.dart` has no test, since it only calls `runApp`.
- **Files:** snake_case names, one main public class per file.

## Out of scope
- Navigation and routing (ticket 1.13).
- Lint rules (1.3), Riverpod (1.4), Drift (1.5).
- Creating folders for features, `core/` or `data/database/` before something goes in them.

## Acceptance criteria
- [x] `lib/` contains only `main.dart` and `src/`, and `src/` contains `app.dart` and `home_screen.dart`.
- [x] `main.dart` only calls `runApp` with `NaVrhApp`, imported with a package import.
- [x] `test/widget_test.dart` is gone. `test/src/app_test.dart` and `test/src/home_screen_test.dart` exist, mirror their source files, and pass.
- [x] `fvm flutter run`, `fvm flutter test` and `fvm flutter analyze` still work.
- [x] `app/README.md` has a "Project structure and conventions" section covering the rules above.

## Decisions
1. **Three layers per feature** (`data/`, `domain/`, `presentation/`), because `domain/` is where the spec's unit-tested logic lives.
2. **Drift tables in a shared `data/database/`**, not split per feature, because routes, photos and expeditions reference each other and one place keeps the schema and migrations (1.10) together.
3. **Package imports everywhere**, for consistency.
4. **`lib/src/` and `test/src/`**: all app code under `src/`, with tests mirroring it.
5. **Home is part of the app layer, not a feature**, for the reasons above.
