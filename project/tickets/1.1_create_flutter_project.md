# 1.1 Create the Flutter project

**Epic:** 1, Project foundations (see [epics.md](../epics.md))
**Spec refs:** section 14 of [SPEC.md](../SPEC.md) (Tech stack: Flutter, Android only)
**Depends on:** nothing

## Why
Everything else builds on this. The goal is a clean, runnable Flutter app and nothing more, so later tickets start from a known base.

## Scope
- Create the Flutter project, Android platform only.
- Remove the default counter demo and replace it with a blank home screen showing the app name.
- Set the app name to `na_vrh` (placeholder, can change before release) and a real package ID.
- Pin the Flutter and Dart versions for the project.
- Add a project `.gitignore` that covers Flutter and Android build output.
- Add a short README with how to install the pinned Flutter version, run the app, and run the tests.

## Out of scope
- Folder structure inside `lib/` (ticket 1.2).
- Lint rules (1.3), Riverpod (1.4), Drift (1.5).
- App icon, signing, store listing (epic 13).

## Acceptance criteria
- [ ] `flutter run` launches the app on an Android device or emulator and shows the blank home screen.
- [ ] `flutter test` passes (a single smoke test that the home screen renders is enough).
- [ ] No iOS, web, or desktop folders exist in the project.
- [ ] The pinned Flutter version is recorded in a file in the repo, and the README says how to use it.
- [ ] A fresh clone can follow the README and run the app with no other steps.

## Technical notes
- Create with `flutter create --platforms=android --org <your.org> --project-name na_vrh`.
- Android `minSdk`: keep Flutter's default unless a later package needs higher. The decision can wait until geolocator and image_picker are added.
- The Dart pipeline script (epic 2) will be a separate package in the same repo, so the app's location in the repo matters (see decision 1).

## Open decisions
1. **Where the app lives in the repo:** at the repo root, or in a subfolder like `app/`? Recommendation: `app/`, with the pipeline script later in `tools/peak_pipeline/`. That keeps the two Dart projects and the docs separated.
2. **Package ID:** which reverse-domain ID (e.g. `com.yourname.navrh`)? It is painful to change after a Play Store release.
3. **Version pinning:** FVM, a `.tool-versions` file, or just the `environment:` constraints in `pubspec.yaml`?
