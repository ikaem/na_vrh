# 1.1 Create the Flutter project

**Epic:** 1, Project foundations (see [epics.md](../epics.md))
**Spec refs:** section 14 of [SPEC.md](../SPEC.md) (Tech stack: Flutter, Android first, iOS ready)
**Depends on:** nothing

## Why
Everything else builds on this. The goal is a clean, runnable Flutter app and nothing more, so later tickets start from a known base.

## Scope
- Create the Flutter project in `app/` with the Android and iOS platforms.
- Remove the default counter demo and replace it with a blank home screen showing the app name.
- Set the app name to `na_vrh` (placeholder, can change before release) and the package ID `xyz.imkaem.navrh` on both platforms.
- Pin the Flutter and Dart versions with FVM in a single `.fvmrc` at the repo root, shared by every Dart and Flutter package, and commit the FVM config.
- Add a root `.gitignore` for monorepo-wide tooling files (OS and IDE files, `.dart_tool/`, the local FVM SDK link, Kotlin session files). The Flutter, Android, and iOS build output rules come from the `.gitignore` files that `flutter create` generates.
- Add two READMEs: a root README (repo layout, FVM setup, how to update the Flutter version) and an app README (requirements, run, test), each covering only its own area.
- Add VS Code launch configurations (`.vscode/launch.json`) so the app can be run from the repo root. FVM also keeps `.vscode/settings.json` pointing VS Code at the pinned SDK.

## Out of scope
- Folder structure inside `lib/` (ticket 1.2).
- Lint rules (1.3), Riverpod (1.4), Drift (1.5).
- The Makefile for running, testing, and building (separate ticket in epic 1).
- Building, running, or testing on iOS. Android is the target for now, and the iOS folder is only generated so it is ready later.
- iOS permission strings, signing, and any Apple developer setup.
- App icon, signing, store listing (epic 13).

## Acceptance criteria
- [ ] `fvm flutter run` launches the app on an Android device or emulator and shows the blank home screen.
- [x] `fvm flutter test` passes (a single smoke test that the home screen renders is enough).
- [x] `app/` contains `android/` and `ios/`, and no web or desktop folders.
- [x] The Android application ID and the iOS bundle identifier are both `xyz.imkaem.navrh`.
- [x] The FVM config (`.fvmrc`) is committed at the repo root and pins the Flutter version, and the root README explains how to use and update it.
- [x] Build output for Android and iOS and the local FVM SDK link are gitignored.
- [x] A fresh clone can follow the READMEs and set up the app with no other steps.
- [x] `.vscode/launch.json` has launch configurations that run the app from the repo root.

## Technical notes
- Create with `fvm flutter create --platforms=android,ios --org xyz.imkaem --project-name na_vrh app`. Flutter's generated defaults will differ from the chosen package ID (it derives it from the project name, and underscores are not valid in an iOS bundle identifier), so set `xyz.imkaem.navrh` explicitly in the Android and iOS configs afterwards.
- `flutter create` can generate the `ios/` folder on Linux, but iOS cannot be built here. That needs a Mac, which is why iOS is out of scope for this ticket.
- Android `minSdk`: keep Flutter's default unless a later package needs higher. The decision can wait until geolocator and image_picker are added.
- The Dart pipeline script (epic 2) will live in `tools/peak_pipeline/`, outside `app/`.
- The pin was created with `fvm use 3.50.0 --force` at the repo root. `--force` is needed because the root has no `pubspec.yaml`.
- The Android build was verified with `fvm flutter build apk --debug`. Building needs a JDK, which Flutter currently finds only through Android Studio (see the JDK item in [todo.md](../todo.md)).

## Decisions
1. **Repo layout:** a monorepo. The Flutter app lives in `app/`. Other parts will get their own top-level folders later (for example `tools/`, and possibly a server or watch app).
2. **Package ID:** `xyz.imkaem.navrh`, based on the imkaem.xyz domain.
3. **Version pinning:** FVM, with a single pin at the repo root. This changed during implementation from the original plan of pinning inside `app/`, so every Dart and Flutter package in the monorepo uses the same version.
