# 1.7 Route table

**Epic:** 1, Project foundations (see [epics.md](../epics.md))
**Spec refs:** sections 2, 6A, 8, 10 and 11 of [SPEC.md](../SPEC.md) (Terminology, Timed routes, Expedition management, Data model, Manual entries)
**Depends on:** 1.6
**Status:** Todo

## Why
A route is one target (a peak) within an expedition. One record carries it through its whole life: planned, started, completed. The detection and timing features (epics 6 and 7) and the history screen read and write this table.

## Scope
- Add the enums as pure Dart in a new feature folder, `lib/src/features/expeditions/domain/` (no Drift or Flutter imports):
  - `RouteState`: `planned`, `started`, `completed`
  - `RouteSource`: `gps`, `manual`
  - `EstimationMethod`: `averaging`, `triangulation`
- Add `lib/src/data/database/tables/routes.dart`: a Drift table `Routes`, with the row class named `RouteRow` (`@DataClassName('RouteRow')`).

  | Column | Type | Notes |
  |---|---|---|
  | `id` | text, primary key | UUID |
  | `expeditionId` | text | foreign key to `expeditions.id`, `ON DELETE CASCADE` |
  | `peakOsmId` | integer | OSM IDs are large integers |
  | `peakName` | text | snapshot of the peak at planning time |
  | `peakLat`, `peakLon` | real | snapshot |
  | `peakElevation` | real, nullable | snapshot, elevation can be missing |
  | `state` | text enum `RouteState` | |
  | `createdAt` | date and time (UTC) | |
  | `startedAt` | date and time, nullable | |
  | `startLat`, `startLon`, `startAccuracyM` | real, nullable | GPS fix at Start |
  | `climbedAt` | date and time, nullable | GPS timestamp, set when completed |
  | `durationS` | integer, nullable | |
  | `source` | text enum `RouteSource` | |
  | `toleranceM` | real, nullable | the tolerance used, set at detection |
  | `estimatedLat`, `estimatedLon`, `distanceM` | real, nullable | set at detection |
  | `estimationMethod` | text enum `EstimationMethod`, nullable | set at detection |
  | `coverPhotoId` | text, nullable | plain column, no foreign key (see 1.6) |
  | `notes` | text, nullable | |

- Add an index on `expeditionId`, so finding an expedition's routes and cascading deletes do not scan the whole table. Check Drift's current index annotation in its documentation.
- Register the table in `AppDatabase` and regenerate (the generated file is committed).
- Add fixture helpers in `test/helpers/` to insert a minimal expedition and a minimal route, for this ticket and for 1.8 and 1.9.
- Update the README boundaries line: `data/database/` may import a feature's pure-Dart `domain/` enums.
- Update SPEC.md section 10: `tolerance_m` is nullable, since a planned or manual route has no tolerance yet.

## Out of scope
- Rules between fields (for example "a completed route has `climbedAt`"). That is domain logic for the later epics.
- Repositories and domain models.
- Moving a route between expeditions (epic 4).

## Technical notes
- **Checked ahead of time** on a throwaway copy:
  - A text enum column stored the enum name (`planned`) and read it back.
  - `ON DELETE CASCADE` and `ON DELETE SET NULL` both worked with the foreign-key pragma from 1.5, and inserting a row with a missing parent was rejected with a `SqliteException`.
  - **A table called `Routes` generates a row class `Route`, which collides with Flutter's own `Route` class.** A file importing both gets an `ambiguous_import` error. That is why the row class is `RouteRow`. Do not name any class `Route` in files that import Flutter.
- Text enums are stored by name, so adding a value is safe, but renaming or removing one breaks existing rows. Be careful once the app has real data.
- **Enum location:** the enums are domain vocabulary, so they live in the feature's `domain/` folder, and the shared table file imports them. This reverses nothing: the domain imports nothing from the data layer, and the data layer imports the domain.
- The peak snapshot columns are copies, not a link to the bundled peaks, so old routes stay readable if peak data changes (SPEC.md section 4).
- Database rules for a completed route (which columns must be set) are deliberately not enforced here. Check constraints could be added later if they prove useful.

## Decisions
1. **`RouteRow` for the row class,** because of the `Route` clash above.
2. **Enums in `features/expeditions/domain/`,** with `data/database/` allowed to import them.
3. **Nullable `toleranceM`,** with SPEC.md corrected to match.
4. **Both estimation methods in the enum** (`averaging`, `triangulation`), since both are to be tested (SPEC.md section 6.3).
